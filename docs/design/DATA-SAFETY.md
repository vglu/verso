# MDViewer — Data Safety: чтение, запись, кодировки, черновики, конфликты, сессия

> Конституция: «не теряем данные» и «round-trip байт-в-байт». Этот документ — как именно. Реализация: Rust `fsops/` + `commands/` (MVP-2), TS-обвязка в сторах.

## 1. Модель владения

- На диске — истина прошлого (`baseMtimeMs` в FileMeta фиксирует, ЧТО мы читали).
- В памяти CM6 — истина настоящего (`\n`-нормализованный текст).
- В `{appdata}/drafts/` — страховка настоящего (черновик, обновляется дебаунсом).

Файл пользователя обновляется ТОЛЬКО явным Save. Автосохранение пишет черновик, не файл (решение: не как Obsidian — мы гость в чужой папке; см. §4).

## 2. Чтение (`read_file`)

Порядок:

1. `fs::read` → bytes. `> 50 МБ` → `Io("file too large")` (MVP-лимит, сообщение в UI).
2. Бинарник-эвристика: NUL-байт в первых 8 КБ (после BOM-анализа UTF-16) → `IsBinary`.
3. Детект кодировки: BOM UTF-8 / UTF-16LE / UTF-16BE → соответствующий decode (`encoding_rs`). Без BOM: валидный UTF-8 → utf-8; иначе → `UnsupportedEncoding` → UI открывает **readonly** с lossy-декодом и жёлтой плашкой «кодировка не поддерживается, файл только для чтения» (никогда не пересохраняем то, что не сможем закодировать обратно).
4. EOL: посчитать `\r\n` vs одиночные `\n`; `eol = crlf` если CRLF ≥ 50% строк; нормализовать всё в `\n`.
5. `trailingNewline` = заканчивался ли файл переводом строки.
6. Вернуть `OpenedFile { meta, content }`; каталог файла → asset-scope; путь → recentFiles.

## 3. Запись (`save_file`) — атомарная

```
1. если baseMtimeMs != null: stat(path).mtime > baseMtimeMs → Err(ExternalModified) [ни байта не писать]
2. encode: content ('\n') → eol из meta (lf|crlf) → bytes в encoding из meta (+BOM если был)
   trailingNewline: привести хвост к исходному состоянию ТОЛЬКО если пользователь его не менял
   (правило: если content уже кончается '\n' — оставить как есть; если нет и оригинал имел — добавить)
3. tmp = тот же каталог, имя ".{file}.mdviewer-tmp-{rand}"  [тот же том — rename атомарен]
4. write(tmp) → fsync(tmp)
5. сохранить permissions оригинала (Unix: mode; Win: readonly-бит уже отсёкся раньше)
6. rename(tmp, path)  [атомарная замена; Windows: std rename поверх существующего = ReplaceFile-семантика; при ошибке доступа (антивирус/индексатор) — 3 ретрая с backoff 50/150/400 мс]
7. fsync(родительский каталог) на Unix
8. stat → вернуть SaveResult { mtimeMs }
9. при любой ошибке: удалить tmp, файл пользователя не тронут
```

Тест-обязательства (cargo): round-trip всех комбинаций {utf-8, utf-8-bom, utf-16-le, utf-16-be} × {lf, crlf} × {с/без trailing newline}; «сохранение без правок = байт-в-байт»; симуляция падения между 4 и 6 (tmp остаётся, оригинал цел, tmp-мусор чистится при старте приложения).

**Watcher-эхо:** свой save вызовет `fs:changed`. TS-сторона игнорирует событие, если `mtimeMs` совпадает с только что полученным из SaveResult (окно 2 сек).

## 4. Черновики (autosave + crash recovery)

- Триггер: любое изменение документа → debounce `autosaveDraftMs` (800) → `draft_save(docId, path, baseMtimeMs, content)`.
- Хранение: `{appdata}/drafts/{docId}.json`, атомарно тем же механизмом §3.
- Удаление: успешный Save; закрытие вкладки с явным «Не сохранять»; принятие «Оставить моё»/«Перезагрузить» в конфликте.
- **Recovery при старте:** `drafts_list()` → для каждого: файл существует и `draft.savedAtMs > file.mtimeMs` → баннер «Найден несохранённый черновик [имя] от [время]: [Восстановить] [Показать файл с диска] [Удалить черновик]». «Восстановить» = открыть вкладку с контентом черновика, dirty=true (пользователь сам решает сохранить).
- Закрытие вкладки/приложения с dirty: диалог «Сохранить изменения в X?» [Сохранить] [Не сохранять] [Отмена]. «Не сохранять» удаляет черновик (осознанный отказ). Убийство процесса — черновик остаётся → recovery.

## 5. Конфликты с внешним миром

| Ситуация | Поведение |
| --- | --- |
| `fs:changed(modified)`, вкладка чистая | Тихо перечитать; курсор/скролл сохранить (map позиции по diff — упрощённо: сохранить номер строки) |
| `fs:changed(modified)`, вкладка dirty | ConflictBanner (не модал!): «Файл изменён другой программой» [Перезагрузить (моё в черновике останется)] [Оставить моё] |
| `save_file` → `ExternalModified` | Тот же баннер; [Оставить моё] → повторный `save_file(baseMtimeMs: null)` |
| `fs:changed(removed/renamed)` | Плашка в табе «файл удалён/переименован снаружи»; контент живёт в памяти+черновике; Save → «Сохранить как» либо восстановить путь |
| Readonly файл / нет прав | Вкладка readonly, плашка; Save → «Сохранить как» |
| Файл на сетевом/удалённом диске пропал (IO error при stat) | Не паниковать: пометить вкладку «недоступен», ретрай при фокусе окна |

Фокус окна = дешёвая точка сверки: `onFocus` → `stat_file` всех открытых вкладок (mtime разошёлся, а watcher проспал — та же логика, что `fs:changed`).

## 6. Сессия

- `SessionState` (IPC-CONTRACT §1) сохраняется: смена вкладок/панелей → debounce 2 c; выход — финальный flush (`onCloseRequested`).
- Restore при старте (если `settings.restoreSession`): argv-файлы имеют приоритет и добавляются К восстановленным вкладкам (активной становится argv-вкладка).
- Файл сессии бит/отсутствует → пустое состояние без ошибок (лог warn).
- Отдельно: `tauri-plugin-window-state` восстанавливает геометрию окна — не смешивать с нашей сессией.

## 7. Что НЕ делаем в MVP (осознанно)

- Diff-merge конфликтов («Сравнить») — фаза 2, place в ConflictBanner заложен.
- История версий файла — фаза 2 (папка snapshots по модели Obsidian).
- Кодировки за пределами UTF-8/16 (cp1251 и др.) — readonly-просмотр есть, конвертация — фаза 2.
