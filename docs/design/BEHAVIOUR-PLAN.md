# Verso — рабочий план по поведению редактора

*Версия: 2026-08-19. Составлено по матрице поведения + три критики, всё сверено с кодом. Русский — проза, английский — идентификаторы и пути. Номера строк проверены на текущем рабочем дереве; строки в исходной матрице были устаревшими примерно на 200 строк по `livePreview/index.ts`.*

---

## 0. Контракт продукта (всё ниже оценивается против него)

Четыре обещания. Нарушение любого из них — дефект класса D, независимо от того, насколько мал баг.

1. **Байты.** Verso не меняет байты, которых пользователь не набирал. Ни при открытии, ни при сохранении, ни при вставке блока.
2. **Подмена.** Verso никогда не подставляет содержимое молча. Черновик, перезагрузка с диска, восстановление сессии — всё это события, о которых пользователь узнаёт.
3. **Позиция.** Никакое действие, которое инициировал не пользователь (async-рендер, перезагрузка, смена темы, ресайз), не двигает то, что он читает.
4. **Видимость.** Каретка не стоит там, где её не видно. Правка не происходит там, где её не видно.

Отдельно — **инвариант чтения**: свежеоткрытый документ является поверхностью для чтения, а не для правки. Ничего не раскрывается, пока пользователь не проявил намерение править. Это лучшее свойство продукта; ни одна волна работ не имеет права его ослабить.

**Шкала серьёзности** (заменяет «blocker/major/minor», который смешивал потерю данных с мёртвой клавишей):

| Класс | Значение | Правило релиза |
|---|---|---|
| **D** | нарушение целостности данных или контракта 1–2 | блокирует релиз |
| **U** | ключевое взаимодействие не работает или работает вслепую | блокирует релиз |
| **G** | деградация: работает, но хуже ожидаемого | не блокирует |
| **P** | полировка / бэклог | не блокирует |

**Корректировка к UX-критике №2 (важно, экономит недели).** Утверждение «`setEditing(true)` выводит из режима чтения весь документ» неверно. `editingField` — глобальный флаг, но он лишь *разрешает* раскрытие; область раскрытия считает `computeActive` и она ограничена строками, которых касается выделение (`active.ts:17–37`). После первого клика раскрывается строка под кареткой, а не документ. Пер-блочный `StateField` не нужен.

**Корректировка к UX-критике №1 (меняет порядок волн).** «Разморозка обнажит D4/E2» — по большей части наоборот. Невидимая ходьба каретки по скрытым `|` возможна **только в замороженном состоянии**: как только `editingField = true`, каретка внутри диапазона блока делает его активным и блок показывает исходник в той же транзакции (`index.ts:743–753`, `active.ts:48–51`). Разморозка эту дыру закрывает, а не открывает. Сохранить нужно одно требование из критики: D1/D2 (goal column) должны ехать в одной волне с разморозкой, иначе стрелка вниз в таблицу будет видимой, но с потерянной колонкой.

### 1.6 Инварианты — не регрессировать

Это то, чем продукт уже выигрывает. Каждая волна проверяется на то, что не сломала ни один пункт.

1. **Автосейв не трогает документ** (`tabs.svelte.ts:208–224`) — иммунитет к самой частой жалобе на markdown-редакторы.
2. **Файл не переформатируется** — ни при открытии, ни при сохранении; кодировка, EOL, финальный перевод строки запоминаются; запись атомарная (кроме дефекта H1′).
3. **Фенсы — это текст, а не виджеты** — весь класс «каретка застряла в блоке кода» отсутствует по конструкции.
4. **Клик по тексту не двигает вьюпорт.**
5. **Перемещение блока байт-точное** — `swapBlocks` переставляет срезы дословно, разделитель остаётся на месте (`blockNav.ts:121–156`). Любая будущая «уборка пустых строк» здесь ломает контракт 1.
6. **Ctrl+L / Ctrl+Alt+↑↓ / Alt+←→** — выделение блока, навигация по заголовкам, история прыжков со скроллом. Ни у одного специализированного markdown-редактора этого набора нет.
7. **Позиция каретки и скролла переживает перезапуск и переключение вкладок** (с оговоркой A6).
8. **Свежий документ не раскрывает разметку.**
9. **Source mode как аварийный выход** — Ctrl+/, персистится, применяется ко всем вкладкам (`createEditor.ts:108, 227–232`, `EditorHost.svelte:20–23, 66`). Он делает часть дефектов «неудобными», а не «непроходимыми», и это надо учитывать при оценке серьёзности.
10. **Черновик пишется в отдельный JSON**, не в файл пользователя.

### Волна 5. Контракт каретки у блоков — M, после Волны 1

- Атомарность блочных диапазонов **только при `isFrozen`** и **только для движения**; удаление, пересекающее замороженный блок, отклоняется `transactionFilter` (**D4, E4**). Наивная реализация через `atomicRanges` строго хуже текущего состояния — один Backspace уничтожит таблицу целиком.
- `HrWidget` и инлайновый `MathWidget` получают `ignoreEvent(): false` и постановку каретки (**C2**, в исправленной формулировке).
- Окно сканирования инлайн-математики расширяется на экран (**D10**).
- Раскрытие ограничивается: только head выделения, и никакого массового раскрытия при выделении шире N строк (**E17, E18**).

### Волна 6. Клавиатурная модель таблиц — L, после Волн 1 и 5

Резолв колонки по клику; Tab / Shift+Tab между ячейками; ↑/↓ между строками; Esc — выход из таблицы; Tab в последней ячейке создаёт строку. Всё — чистое движение каретки и вставка текста, никакой ре-сериализации.

**Единственный настоящий риск байт-точности во всём плане** — новая строка. Безопасная реализация копирует форму `|`-и-пробелов предыдущей строки дословно. Соблазнительная («выровнять по ширинам колонок») — один шаг от нормализации всей таблицы, то есть от того самого дефекта Typora, ради иммунитета к которому существует контракт 1. До первой строки кода в `tests/fixtures` кладётся таблица с нарочито рваными пайпами и тест на неизменность байтов.

Закрывает: E5 (полностью), E6, E7, E8, F11.

### Волна 7. Создание документа — M, после Волны 2

New File в `menu.rs` + Ctrl+N + «New file here» в дереве + подключение `openUntitled()`; черновики ключуются по `tab.id`, когда пути нет (**H4**); первый Save As усыновляет путь — переезд ключа черновика, регистрация в watcher, переименование вкладки; `EmptyState` получает кнопку создания.

Закрывает: H4, J-сценарии (создание документа), часть первого запуска.

### Волна 8. Поиск и палитра — M, после Волны 4

Палитра переходов по заголовкам на **Ctrl+P** (хук `onGoToHeading` уже прокинут через `createEditor`, `EditorHost.svelte:66` его просто не передаёт); тот же индекс используется фильтром в оглавлении (**I10**); Esc из поиска возвращает к позиции до поиска (**C14**, требует Волны 4); метки совпадений на дорожке скролла (**C15**); честная строка о том, что поиск идёт по **исходнику**, а не по отрисованному тексту — заголовок, найденный глазами, может не находиться поиском.

### Волна 9. Производительность — M, после Волны 5

Инкрементальный пересчёт блочного слоя по изменённому диапазону; `scanDisplayMath` перестаёт обходить весь документ на каждое нажатие; инлайн-слой перестаёт полностью перестраиваться на каждое движение каретки. Бюджеты — в §4.

### Волна 10. Сворачивание секций — L, после Волн 3 и 4

Fold по заголовкам и спискам, fold-all/unfold-all. Ставится последней намеренно: сворачивание меняет `visibleRanges`, на которые опирается подсветка оглавления (Волна 3), и требует прокидывания позиций (Волна 4).

### Волна 11. Долги, которые надо признать — M/L

Frontmatter (**N10**); IME/composition (**N7**); watcher переживающий rename (**N9**); a11y-минимум: `role="alert"` на `Banner`, focus trap и восстановление фокуса в `Modal`, `aria-current` в оглавлении, roving tabindex на тулбаре и оглавлении, `@media (forced-colors: active)`; контекстное меню правой кнопкой; локализация нативного меню.

## 4. Как проверять

Общее правило: **каждая волна проверяется на всех четырёх фикстурах** — `sample.md` (инлайн), `blocks.md` (таблица), `rich.md` (формулы + диаграмма), `real-doc.md` (длинный реальный текст) — и каждая проверка начинается с **свежего запуска приложения**, потому что почти весь класс U проявляется только до первого взаимодействия.

**Волна 0.** Ctrl+E в `sample.md` с выделенным словом → включается только reader mode, backticks не появляются. Ctrl+Shift+O → открывается диалог выбора папки. Ctrl+F, курсор в поле поиска, Ctrl+E → ничего не происходит. F3 после поиска → переход к следующему совпадению. Alt+↓ на строке внутри абзаца → едет одна строка; Ctrl+Shift+↓ → едет весь блок. Alt+← при пустой истории → каретка не двигается.

**Волна 1.** `sample.md`, свежий запуск, один клик в середину `жирный` → `**` видны немедленно. `blocks.md`, свежий запуск, один клик по ячейке → таблица показывает исходник, каретка в этой ячейке. `rich.md`, свежий запуск, клик по диаграмме → виден исходник mermaid. Свежий запуск, кнопка «Таблица» в тулбаре → появляется исходник таблицы с кареткой в первой ячейке заголовка, а не отрисованная таблица. Свежий запуск, Enter в конце строки → строка раскрылась, изменение видно. `blocks.md`, каретка в конце длинной строки абзаца над таблицей, ↓ → каретка в первой строке таблицы **примерно в той же колонке**, таблица раскрыта. Отдельно: переключиться на японскую IME, свежий файл, набрать одно слово и подтвердить → слово должно вставиться целиком, не ромадзи.

**Волна 2.** Внешне изменить открытый чистый файл → вкладка перезагрузилась, позиция скролла сохранилась, показано уведомление. Ctrl+Z → либо ничего не происходит, либо сохранение после него упирается в баннер конфликта. Спровоцировать конфликт, «Keep mine», повторить внешнее изменение → баннер появляется **снова**. Убить процесс с несохранённым текстом, открыть файл заново из проводника → баннер Restore/Discard, содержимое на экране — дисковое, пока не нажат Restore. Ctrl+E → чип «Reader» в статусной строке, тулбар серый, печать не меняет ни файл, ни заголовок вкладки, чекбокс задачи не переключается. Файл со смешанными CRLF/LF: открыть, добавить один символ, сохранить, сравнить в `git diff` → изменена одна строка, не весь файл.

**Волна 3.** `real-doc.md`, свежий запуск: число пунктов в оглавлении совпадает с числом заголовков **до** любой правки. Прокрутить колесом на середину, не трогая каретку → подсветка в оглавлении едет за экраном. Прокрутить так, чтобы заголовок ушёл за верх → появились крошки; клик по крошке → переход к началу секции; Alt+← → возврат.

**Волна 4.** `rich.md`: прокрутить так, чтобы диаграмма была в середине экрана; закрыть приложение; открыть → диаграмма на том же месте (допуск — половина строки). То же для переключения вкладок и для Alt+←. Сценарий на N4: прыгнуть на заголовок в середине, вернуться Alt+←, добавить три абзаца **выше** этой позиции, снова прыгнуть и вернуться → возврат туда же, а не со сдвигом. Пролистать `rich.md` сверху вниз одним движением → нет ни одного рывка на диаграммах и картинках.

**Волна 5.** `blocks.md`, свежий запуск, каретка в абзаце над таблицей, →→→ до края таблицы → каретка перескакивает таблицу целиком одним шагом либо таблица раскрывается; невидимого прохода по `|` быть не должно. Там же Backspace на границе → либо ничего, либо удаление всей таблицы **после подтверждения**, но не молчаливое исчезновение одного пайпа. Ctrl+A на `rich.md` → документ остаётся отрисованным. Протяжка мышью через три абзаца → текст под курсором не дёргается. Каретка на заголовок → текст заголовка **не сдвигается** вправо. `---` в `sample.md`: клик → каретка встала. Формула на границе экрана: медленно скроллить → рендерится, а не показывает `$...$`.

**Волна 6.** `blocks.md`: клик по третьей колонке второй строки → каретка внутри слова этой ячейки. Tab → следующая ячейка, Shift+Tab → назад, ↓ → та же колонка строкой ниже, Esc → каретка после таблицы. Tab в последней ячейке → новая строка. **Обязательно:** взять таблицу с рваными пробелами, пройти Tab'ом по всем ячейкам без ввода, сохранить → `git diff` пустой.

**Волна 7.** Ctrl+N → новая вкладка. Набрать текст, убить процесс, запустить → баннер восстановления, текст на месте. Save As → вкладка переименована, файл на диске, повторное внешнее изменение ловится watcher'ом.

**Волна 9 — бюджеты (числа, а не ощущения).** На `real-doc.md`, размноженном до 10k слов и 200 заголовков: keystroke→paint p95 < 16 мс. Открытие файла 1 МБ → первая отрисовка < 300 мс. Переключение вкладки < 50 мс. Пересчёт оглавления < 100 мс. Сохранение < 100 мс. Прокрутка мимо 20 mermaid-блоков — устойчивые 60 fps. Замеры делаются профайлером, результат пишется в `tests/perf.test.ts` как регрессионный порог.

**Чего проверка кодом не даст.** У проекта 14 unit-файлов и ни одного e2e. Значительная часть строк «matches» в исходной матрице получена чтением кода — и именно там чтение ошиблось трижды (B12, E13, C2). Любая строка со статусом «работает» без ручного прогона на четырёх фикстурах считается непроверенной.

## 5. Осознанно не делаем

**Reader mode как полноценный режим чтения.** Не расширяем: не прячем тулбар, не меняем measure, не персистим по вкладкам. Основание — по собственным же данным матрицы, режим по умолчанию (замороженный, отрисованный, без раскрытия) уже является чистым чтением; reader mode не предлагает ничего сверх этого, кроме скрытой каретки. В Волне 2 он становится безопасным (read-only + видимый чип) — и на этом всё. **Триггер пересмотра:** если после Волны 3 (крошки + прогресс) появится запрос на «спрятать всё», режим станет носителем этой функции; если запроса не будет — удалить вместе с клавишей.

**Пер-блочное состояние редактирования.** Не делаем. `editingField` глобален по документу, но раскрытие и так ограничено строками выделения (`active.ts:17–37`), поэтому «первый клик расфризит весь документ» — это не то, что произойдёт. Отдельный `StateField` на блок стоил бы недели и не купил бы ничего наблюдаемого.

**Адаптивное появление/скрытие хрома по длине документа (A3, I12).** `outlineVisible` — явная настройка пользователя. Автоматика, переопределяющая явный тумблер, хуже, чем всегда включённый хром. Максимум, что допустимо, — значение по умолчанию для документа, которого пользователь ещё не видел, и это не стоит менять форму состояния (сегодня флаг глобальный, пришлось бы делать его повкладочным).

**Сужение measure с 760px до 680px (B3).** Цитата, которой это обосновывалось, говорит про носитель (экран против бумаги), а не про длину строки; литература по длине строки (Dyson & Haselgrove) даёт сопоставимую производительность в диапазоне 55–100 знаков. Менять дефолт, который заметит каждый существующий пользователь, ради фольклорной цифры — не стоит. Что сделать дёшево: выразить настройку в `ch`, чтобы она не разъезжалась при Ctrl+= / Ctrl+−.

**Ctrl+K O и любые аккордные префиксы на клавишах с одиночным действием.** Ctrl+K — это вставка ссылки; превращать её в префикс значит добавить задержку к ежедневному действию.

**Перетаскивание блоков мышью за ручку (G6).** Продукт клавиатурный; Alt/Ctrl+Shift+↑↓ уже дают перемещение блока лучше, чем у конкурентов.

**Симметричное движение по словам (C8).** Асимметрия — общая для всех редакторов; жалоба, на которую ссылалась матрица, была отклонена самими модераторами.

**Разбиение матрицы на «аудит» и «бэклог» как отдельные документы.** Сделано внутри этого файла: §1.2–1.4 — работа, §1.5 — бэклог, §1.6 — инварианты. Отдельный файл-аудит заведётся только если начнёт расходиться с кодом.

**Печать/экспорт PDF, спелчекинг, второе окно, RTL.** Признаны настоящими пробелами (§1.5), но в план волн не входят: у каждого либо нет доказанного спроса, либо цена (виртуализация CodeMirror при печати, словари, синхронизация синглтонов сессии) несопоставима с ценностью на текущем этапе. Каждый попадёт в план, когда придёт первая настоящая жалоба — и это осознанное решение, а не забывчивость.

## 6. Где план может ошибаться

Честный список неопределённостей, чтобы они не выглядели фактами.

- **N7 (IME)** — рассуждение по коду, не воспроизведено. Может оказаться, что CodeMirror сам гасит проблему через `EditorView.composing`. Проверять до планирования работ.
- **N9 (watcher и rename)** — поведение `notify` на Windows при подмене файла не проверено вживую. Может работать.
- **I5** — вероятно не баг; помечено как требующее ручной проверки.
- **E2 (ввод внутри скрытого маркера)** — в исходной матрице оценено как major. Инлайновые маркеры атомарны (`index.ts:120–125`), поэтому каретка туда обычно не попадает; реальная поверхность уже, чем заявлено, и сводится к программно поставленным выделениям (чип фенса). Отдельная работа заводится только если воспроизведётся.
- **D11** (включительная граница `isRangeActive`) — выглядит намеренным; менять без жалобы не нужно.
- **Размеры волн** даны по прочтении кода, без прототипирования. Наименее надёжная оценка — Волна 4 (якорные позиции), там миграция формата сессии может съесть день сверху.
- **Всё, что помечено в §1.1 как «требует ручной проверки»,** — это места, где чтение кода уже один раз ошиблось. Относиться соответственно.
