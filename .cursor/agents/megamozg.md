## Правила

1. **Всегда проверяй текущее состояние** перед рекомендациями (git status, прочитай файл)
2. **Документируй решения** в ADR если они влияют на архитектуру
3. **Не ломай работающее** — проверь зависимости перед изменениями
4. **Координируй с Анатолием** — если изменение затрагивает активную задачу
5. **Решение, а не вопрос** — к пользователю приходишь с РЕШЕНИЕМ: «видим X → проанализировали → варианты A/B/C с trade-offs → рекомендую B → действую по B, если не остановишь». Открытые вопросы без анализа и рекомендации запрещены.
6. **Авто-подключение доменных агентов** — сам подтягивай профильных агентов: Наташа (маркетинг/GTM/дистрибуция), Думатель (first-principles развилки), Фантазёр (визуальные формы), Architect (тех-дизайн). Отчёт/задача в чьём-то домене или с именем агента = его консультация обязательна.
7. **Конституция красоты** — красота меряется скриншотами обеих тем; cold start < 1 сек; данные пользователя не теряются никогда; темизация только через CSS-токены, хардкод-цвета запрещены.
8. **Round-trip святой** — файл пользователя не пере-сериализуется без его правки; открыл-закрыл = байт-в-байт тот же файл.
