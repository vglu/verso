# ADR-003 — Как блок раскрывается под курсором

## Статус

Принято (2026-08-19)

## Контекст

ADR-001 задал live-preview: текст файла — источник истины, разметка рендерится декорациями, а под курсором строка показывает исходник. Модель раскрытия была одна на всё: **отрисовка заменяется исходником**.

На реальных документах это дало класс жалоб, которые сначала выглядели как отдельные баги:

- курсор «перепрыгивал» таблицу целиком в обе стороны;
- вход в таблицу схлопывал сетку в двадцать строк палок, документ ниже подпрыгивал («меня куда-то выкинуло»);
- диаграмму и формулу нельзя было ни открыть кликом, ни оценить результат правки;
- язык у блока кода нельзя было изменить.

Точечные починки (перехват стрелок, клик по виджету) сняли симптомы, но не причину.

## Решение

Модель раскрытия перестаёт быть одна. Различаем по природе разметки, а не по размеру блока.

### 1. Исходник **и есть** содержимое → заменяем отрисовку исходником

Строчные начертания, заголовки, списки, цитаты, ссылки. Слова лежат прямо между маркерами: раскрытие сдвигает строку на несколько символов, пользователь видит всё, что ему нужно. Поведение остаётся прежним, построчным.

### 2. Исходник — **описание**, из которого содержимое получается → показываем оба слоя

Формулы (`$$…$$`), диаграммы (```` ```mermaid ````), картинки. По тексту `\int_{-\infty}^{\infty}` или `graph TD` нельзя судить о результате, поэтому при входе курсора исходник появляется **рядом с отрисовкой, а не вместо неё**: строки исходника показываются, отрисованный блок остаётся ниже как живой предпросмотр.

Так делает Typora, и по той же причине: правишь описание — должен видеть результат.

### 3. Исходник и есть содержимое, но правится **структура** → редактируем в самой отрисовке

Таблицы. Текст ячеек лежит между палками, поэтому показывать оба слоя означало бы дублировать одно и то же. Но при добавлении колонки правится раскладка, а не текст, — значит работать надо в сетке: `Tab` между ячейками, `Enter` — следующая строка, стрелки — по ячейкам. Каждое нажатие пишется **точечной правкой в диапазон таблицы** в markdown-тексте.

Курсор при этом никогда не вызывает схлопывание — жалоба на навигацию исчезает по построению, а не заплаткой.

### Отдельно: режим исходника

Полное отключение декораций (`Ctrl+/`, переключатель в панели) остаётся как общий выход: что бы отрисовка ни делала неудобным, всегда есть режим, где файл виден ровно таким, каким он записан.

## Альтернативы

**Сплит-панель (исходник слева, отрисовка справа).** Снимает весь класс проблем разом — потому что не заходит в него: слева обычный текст, никаких декораций в редактируемой поверхности. Отклонено: у нас нет HTML-рендерера, наша отрисовка — декорации поверх текста. Сплит означает второй рендерер и два визуальных источника истины, которые придётся вечно согласовывать; каждый новый вид блока пришлось бы реализовывать дважды. Один рендерер — принцип, а не экономия.

Решение не окончательное во времени: когда появится экспорт в HTML/PDF, второй рендерер понадобится по существу задачи, и сплит станет его побочным продуктом. Пересмотреть тогда, не раньше.

**Оставить одну модель и чинить навигацию перехватами.** Отклонено: перехваты уже написаны и работают, но величина возмущения остаётся несоразмерной правке — поставить курсор стоит семисот пикселей сдвига.

**`contenteditable`-остров для таблицы с сериализацией на blur.** Отклонено по внешнему ревью: разводит историю отмен, рассинхронизируется с перечитыванием файла извне и делает правило «исходник на строке курсора» непоследовательным ровно для одного вида блока.

## Последствия

- ✅ Курсор больше не роняет раскладку документа; вход в блок перестаёт быть событием.
- ✅ Правка описания сопровождается результатом — как в Typora.
- ✅ Инвариант ADR-001 не нарушен: правки точечные, документ не пересобирается, байт-точность сохраняется.
- ⚠️ Слой раскрытия усложняется: три модели вместо одной. Это оправдано только потому, что различение содержательное, а не по размеру.
- ⚠️ Табличное редактирование в сетке — самостоятельная работа с собственными краевыми случаями (объединение строк, вставка колонок, вставка из буфера). Делается волной, а не разом.
