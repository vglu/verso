# ADR-002 — UI-фреймворк: Svelte 5

## Статус

Принято (2026-08-19)

## Контекст

ADR-001 оставил выбор UI-фреймворка Архитектору с критерием: минимальный bundle size и отсутствие runtime-налога на старт (конституция: cold start < 1 сек). UI-фреймворк в Verso обслуживает только «хром» (вкладки, панели, дерево, настройки) — ядро документа целиком живёт в CodeMirror 6, который framework-agnostic.

## Решение

**Svelte 5 (runes) + Vite + TypeScript strict.**

- Компилируется в vanilla JS: runtime ~10–15 КБ, нулевой налог на старт — лучший показатель среди зрелых фреймворков.
- Реактивность рун (`$state`, `$derived`, `$effect`) идеально ложится на наши сторы (tabs, settings, session) без внешнего state-менеджера.
- Официальный шаблон `create-tauri-app` для Svelte 5 — каркас поднимается за минуты.
- CM6 монтируется в Svelte-компонент как императивный остров (`onMount` → `new EditorView`), фреймворк не трогает документ.

## Альтернативы

- **SolidJS** — сопоставимая производительность, но меньше экосистема/знание, выигрыш ~0.
- **React** — 45+ КБ runtime, VDOM-налог, ничего не даёт для «хрома» из 10 компонентов. Отклонено.
- **Vanilla TS** — максимальный контроль, но ручной DOM-стейт для вкладок/дерева/модалок = медленнее разработка и больше багов. Отклонено.

## Последствия

- ✅ Bundle хрома < 50 КБ; старт определяется webview + CM6, не фреймворком.
- ✅ Один способ писать состояние (руны) — консистентные сторы.
- ⚠️ Никакой логики документа в Svelte-компонентах — граница «CM6 владеет документом, Svelte владеет хромом» обязательна (см. `docs/design/ARCHITECTURE.md`).
